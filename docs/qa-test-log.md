# ShipSafe QA 및 Test 기록

기록일: 2026-11-07

## 1. 현재 목표와 진행 단계

ShipSafe v1.0은 React에서 여러 공개 보안 API의 정보를 조회하고, 결과의 의미와 한계를 설명하는 대시보드다. URL을 입력해 DNS·Shodan·Mozilla 정보를 보고, 패키지 생태계·이름·버전으로 OSV 정보를 조회한다. 사이트에 실제로 공격해 취약점을 검증하는 기능은 현재 범위가 아니다.

현재는 주요 기능 구현 후, 요구사항 충족과 결과 정확성을 검증하고 작성한 코드를 학습하는 단계다. 기능 구현 완료와 과제 제출 준비 완료는 구분한다.

## 2. 개발·검증 진행 과정

1. DNS·Shodan·OSV·Mozilla의 API 연동 가능성을 확인했다.
2. App에 모였던 로직을 페이지·서비스·공통 Hook으로 분리했다.
3. 라이브러리 입력 폼, 취약점 카드, 검사 이력을 구현했다.
4. PL 마스코트와 반응형 대시보드 UI를 적용했다.
5. CDN IP를 원본 서버로 오인할 수 있는 문제를 보완하고 다중 IP 분석을 구현했다.
6. 조회 실패·관측 정보 없음·미검사 상태와 실제 확인/잠재 위험을 구분했다.
7. CVE 번호로 NVD 상세 설명·CVSS·영향 조건을 조회하도록 연결했다.
8. 검사 전 임시 대상 CRUD·검색·유형 필터를 구현했다. 이 목록은 React 상태에만 보관하고, 검사 결과 이력은 별도 localStorage로 관리한다.
9. 전문용어와 영어 이름을 병기하고 기술 원문은 상세 영역으로 정리했다.
10. Mozilla 결과를 개선 권장 / 선택적 추가 보호 / 이번 평가 기준 충족 / 참고·판단 보류로 구분했다. API의 원래 점수는 수정하지 않는다.

## 3. AI를 통해 확인한 검증 결과

| 항목 | 확인 방법 | 결과 |
| --- | --- | --- |
| 코드 검사 | npm run lint | 성공 |
| 자동 테스트 | npm test | 26개 성공. 로직·API 모의 응답·React 정적 렌더링 검증이며 전부 실제 API 호출을 하는 테스트는 아님 |
| 빌드 | npm run build | 성공 |
| 실제 웹사이트 조회 | 기존 브라우저 수동 검증 | example.com의 DNS·IP별 Shodan·Mozilla 조회 확인 |
| 실제 CVE 조회 | 기존 브라우저 수동 검증 | CVE-2021-44228 NVD 조회·CVSS·원문 표시 확인 |
| 검사 대상 CRUD | 2026-11-07 브라우저 수동 검증 | 웹사이트/라이브러리 추가, 수정, 삭제, 검색, 필터 확인 |
| 대상 재사용 | 브라우저 수동 검증 | 검사 화면에 URL 또는 패키지·버전 전달 확인. API 조회는 검사 버튼을 눌러 실행 |
| 임시 목록과 이력 구분 | 브라우저 수동 검증 | 메뉴 이동 시 임시 목록 유지. 새로고침 시 임시 목록 초기화, 저장된 이력 유지 |
| 반응형 | 기존 모바일 390px 검증 | 주요 화면 가로 넘침 없음 |
| 선택 설정 구분 | 최신 자동 렌더링·분류 테스트 | COEP·COOP·CORP는 선택 그룹, 실패 항목·판단 보류·기준 충족과 구분 |

새 분류 UI를 실제 사용자가 보기 쉬운지는 별도 수동 QA로 확인한다. 과거 브라우저 확인은 해당 시점의 결과이며 모든 브라우저·대상을 보장하지 않는다.

## 6. 문제와 개선 기록

| 발견한 문제 | 조치 | 검증 근거 |
| --- | --- | --- |
| Cloudflare IP의 포트를 원본 서버 포트로 오해할 수 있음 | 공식 CIDR 근거와 IP 역할·원본 미확인 표시 | CDN 로직 테스트와 실제 IP 결과 확인 |
| 첫 IP만 조회 | 최대 8 IP·동시 2개·부분 실패 유지 | 자동 테스트 및 실제 IP 2개 조회 |
| CVE가 번호·링크 수준으로만 보임 | NVD 상세 조회 추가 | 실제 NVD 조회와 파싱 테스트 |
| 선택 설정 누락이 필수 개선처럼 보임 | 평가 결과의 표시 그룹 분리 | 자동 분류/렌더링 테스트, 사용자 QA 예정 |
| 쉬운 제목이 오히려 모호함 | 전문용어+영문 이름으로 변경 | 사용자 피드백 반영, 렌더링 테스트 |
| 검사 이력을 검사 전 대상 목록으로 혼동 | 두 탭과 저장 방식을 분리 | 임시 대상 CRUD·새로고침 확인 |

## 7. 남은 제출 준비

- API 출처·조회 시각 표시를 화면별로 최종 점검하고 부족한 곳 보완.
- 사용자가 직접 위 테스트를 수행하고 캡처·실제 결과를 기록.
- 입력→상태→API 호출→결과 렌더링 흐름을 본인의 말로 설명.
- AI 활용 프롬프트·수정 요청·오류 해결 과정과 최종 수행 결과 보고서 작성.
- PRD의 ‘이력 영구 저장 제외’와 현재 localStorage 이력을 비교해 추가 기능/범위로 문서 정리.
- 2026-11-07 추가한 CRUD와 표시 그룹 변경은 아직 커밋·push하지 않음.
